# Архитектура KUMOsystems 1.1

Веб-сервис из двух частей: интерфейс в браузере (React + OpenLayers) и сервер на Python
(FastAPI), который хранит сценарии и планы и выполняет расчет. В рабочем режиме один процесс
сервера отдает и API, и собранный интерфейс. История решений по версиям —
[ARCHITECTURE_HISTORY.md](ARCHITECTURE_HISTORY.md), алгоритм — [ALGORITHM.md](ALGORITHM.md),
API — [API.md](API.md).

```text
Браузер (React 19, TypeScript, OpenLayers 10)
  шаги «Район → Парк → Параметры», карта, результаты, симуляция, архив
        │  JSON по HTTP (GeoJSON WGS84: долгота, широта)
        ▼
FastAPI (Python 3.12, Pydantic 2)                    внешние сервисы (необязательны)
  main.py — API, раздача интерфейса                  Open-Meteo — ветер и порывы
  domain/models.py — контракт и валидация            OpenStreetMap / MapTiler — подложки
  imports/ — KML заказчика                            (запрашивает браузер)
  planning/ — расчетное ядро (Shapely, pyproj, NumPy)
  export/ — GeoJSON, KML, HTML-отчет
  infrastructure/ — БД, настройки PostgreSQL, погода
        │  SQLAlchemy 2
        ▼
SQLite (по умолчанию) или PostgreSQL (схема kumosystems)
```

## Поток данных

1. Оператор рисует или импортирует район, ограничения и площадки, набирает парк и задает
   параметры. Интерфейс хранит черновик с историей отмены и повтора.
2. «Рассчитать план»: сценарий сохраняется как неизменяемый снимок (`POST /api/scenarios`,
   UUID), затем рассчитывается (`POST /api/planning-runs`). Расчет синхронный, в пуле потоков.
3. Ядро переводит геометрию в локальные метры, строит варианты и выбирает лучший по критерию
   ([ALGORITHM.md](ALGORITHM.md)). План сохраняется отдельной записью со ссылкой на снимок.
4. Интерфейс рисует маршруты, показатели, диаграмму расписания и симуляцию по времени.
5. Экспорт и отчет строятся из сохраненного плана без пересчета, поэтому результат в архиве
   воспроизводим и после обновления алгоритма.

## Хранение

Три таблицы с JSON-содержимым: `scenarios` (снимки), `plans`, `aircraft_profiles`
(пользовательские профили). По умолчанию SQLite (`bas.db`). PostgreSQL подключается в интерфейсе
«БД компании» администратором (токен сервера): схема `kumosystems`, TLS, пароль только из
переменной окружения. Переключение не переносит данные.

## Ключевые решения

- **Ядро — чистая функция** `plan(Scenario) → dict` без сети и БД: одинаково работает в API,
  тестах, анализе парка и автономной сборке.
- **Детерминизм.** Одинаковый сценарий дает одинаковый план. 12 эталонных расчетов примеров без
  самолета не менялись побитово с версии 0.7; изменения модели самолета в 1.1 зафиксированы в
  [VERIFICATION.md](VERIFICATION.md).
- **Честность результата.** Каждый план несет статус `demonstration`, версию алгоритма и список
  примененных допущений; невыполнимость — код ошибки с объяснением.
- **Совместимость контракта.** Новые поля сценария необязательны, значения по умолчанию дают
  прежнее поведение; `schema_version` не меняется.
- **Интерфейс без сборщика состояния:** React-хуки, OpenLayers напрямую, стили на CSS-токенах
  (светлая и темная тема).

## Режимы запуска

| Режим | Как | Для чего |
|---|---|---|
| Автономная сборка | ZIP для Windows, `KUMOsystems.cmd` — свой Python и собранный интерфейс | Демонстрация и передача без установки ([WINDOWS_STANDALONE.md](WINDOWS_STANDALONE.md)) |
| Из исходников, один процесс | `run.bat` — сервер отдает собранный `frontend/dist` | Локальная работа ([SINGLE_PROCESS_LAUNCH.md](SINGLE_PROCESS_LAUNCH.md)) |
| Разработка | `uvicorn --reload` + `npm run dev` (Vite проксирует `/api`) | Разработка (README) |
| Контейнеры | `compose.yaml`: PostgreSQL/PostGIS, API, веб | Заготовка, не проверялась |

## Качество

- Сервер: 192 теста pytest — API, расчет, воздушное пространство, камеры и самолет, эшелоны,
  зарядка, импорт KML, архив, запуск сборки. Клиент: 41 тест Node (расписание, симуляция,
  карта, парк, иконки, темы, уровни). TypeScript в строгом режиме.
- Автономная сборка сама проверяет зависимости DLL и запускает собранный сервер без Python.
- Проверки по версиям и замеры — [VERIFICATION.md](VERIFICATION.md).

## Безопасность

Сервер рассчитан на локальный запуск (`127.0.0.1`). Отчет отдается с Content-Security-Policy без
скриптов, все значения экранируются. KML с объявлениями сущностей отклоняется, размер ограничен
25 МБ. Ошибки валидации не возвращают входные данные (в них могут быть строки подключения).
Пароль PostgreSQL не сохраняется. Ключ MapTiler хранится только в локальном `.env.local` и не
попадает в автономную сборку и в пакет исходников. Для общего сервера нужны авторизация и
ограничение запросов ([LIMITATIONS.md](LIMITATIONS.md)).
