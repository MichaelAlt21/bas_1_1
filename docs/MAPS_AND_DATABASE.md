# KUMOsystems 0.4: свои подложки и PostgreSQL компании

## Пользовательские карты

Нажмите «Мои карты» над картой. Поддерживаются:

| Формат | Что вводить |
|---|---|
| MapTiler | Собственный публичный API-ключ и ID карты, например hybrid-v4 |
| XYZ | HTTPS-шаблон растровых тайлов с {z}, {x}, {y} |
| TileJSON | HTTPS-адрес JSON-описания растрового XYZ-источника |

Для XYZ/TileJSON ключ можно подставить через {key} в URL. Значение кодируется как
параметр URL. В поле MapTiler нужен сам ключ, а не ссылка с ключом.
Указывайте атрибуцию правообладателей и поддерживаемый диапазон масштабов.
Пользовательская атрибуция отображается как текст, а не исполняемый HTML.

Образец для локального запуска: выберите TileJSON и укажите
http://127.0.0.1:5173/examples/osm-raster.tilejson.json, атрибуция —
«© OpenStreetMap contributors». Файл frontend/public/examples/osm-raster.tilejson.json
содержит ссылки на стандартные OSM-тайлы и служит примером структуры.

Источник должен использовать Web Mercator / EPSG:3857 и стандартную сетку XYZ 256 px.
Для TileJSON и тайлов нужен доступ браузера к серверу и подходящие CORS-заголовки.
HTTP поддерживается только для localhost; остальные источники требуют HTTPS.
WMS/WMTS, TMS, векторный style.json, GeoTIFF и загрузка офлайн-пакетов еще не реализованы.

Кнопка «Добавить и выбрать» подключает источник. Его можно изменить или удалить.
Удаление выбранного пользовательского источника возвращает карту к OSM.
Выбор подложки не меняет геометрию, результаты и время воспроизведения.
Смена слоя отменяет незавершенную загрузку его TileJSON; поздний ответ старого источника
не заменит новую карту. Ошибки загрузки показываются отдельно от ошибок расчета.

Без флажка сохранения настройки и ключ существуют только в памяти страницы.
С флажком они сохраняются в localStorage этого браузера под ключом kumosystems.maps.v1.
Это не защищенное хранилище секретов и не общий корпоративный каталог карт.
Публичный ключ картографического API в любом случае виден в сетевых запросах браузера.
Используйте предназначенные для frontend ключи и ограничения доменов у провайдера.
Ключи и подложки не включаются в сценарии, планы или экспорт миссий.

Стандартные OSM и MapTiler hybrid-v4 остаются отдельными пунктами. Их ключ и ID
по-прежнему берутся из существующих VITE_MAPTILER_KEY / VITE_MAPTILER_SATELLITE_ID.
Создание пользовательской карты не перезаписывает .env или эти значения.

## Назначение корпоративной БД

PostgreSQL хранит сценарии, пользовательские типы БПЛА и планы KUMOsystems.
Это основное хранилище приложения, не интеграция с произвольными таблицами компании.
PostGIS не обязателен: сейчас данные хранятся как JSON.
Приложение использует отдельную схему kumosystems и три таблицы:
scenarios, plans, aircraft_profiles. Таблицы вне этой схемы не изменяются.

Все пользователи одного API работают с одной выбранной БД. Личные карты остаются
в браузере. Индивидуальная авторизация пользователей и разграничение доступа к сценариям
пока не реализованы; административный токен защищает только настройку подключения.
До доступа из интернета нужны HTTPS, полноценная авторизация и настройка размещения.

## Подготовка администратором

Нужны адрес, порт, база, имя пользователя, пароль и требования к TLS.
Администратор компании создает саму БД и учетную запись.
Для готовой схемы приложению нужны CONNECT к базе, USAGE к схеме, SELECT и INSERT
на таблицы. Подготовка отсутствующих схемы и таблиц требует соответствующих CREATE-прав;
ее может выполнить администратор отдельно, после чего выдать минимальные рабочие права.

Пароль не сохраняется в интерфейсе или JSON-файле конфигурации. Рабочий пароль
берется из переменной окружения сервера, по умолчанию KUMO_DB_PASSWORD.
Она должна быть задана до запуска API. Например, в PowerShell из папки backend:

```powershell
$kumoDbSecret = Read-Host 'Пароль PostgreSQL' -AsSecureString
$env:KUMO_DB_PASSWORD = [System.Net.NetworkCredential]::new('', $kumoDbSecret).Password
.\.venv\Scripts\python.exe -m uvicorn bas.main:app --host 127.0.0.1 --port 8000
```

Команда не содержит пароль в открытом тексте. При запуске API как службы или контейнера
задайте переменную в его окружении через предусмотренный компанией механизм секретов.
Изменение переменной в другом терминале не изменяет окружение уже работающего API.

При первом старте API создает случайный административный токен в .runtime/admin-token
рабочего каталога сервера (при стандартном запуске — backend/.runtime/admin-token).
В отдельном терминале из той же папки backend его можно вывести для вставки в интерфейс:

```powershell
.\.venv\Scripts\python.exe -m bas.configure_database token
```

Команда намеренно показывает токен локальному администратору. Не включайте его в
демонстрационные записи экрана или общий репозиторий. Альтернатива — переменная
KUMO_ADMIN_TOKEN на сервере. Каталог можно изменить через KUMO_SETTINGS_DIR.
Ограничьте доступ к этому каталогу учетной записью сервера; на Windows применяются
также унаследованные ACL папки. Токен не записывается в localStorage браузера.

## Подключение через интерфейс

1. Откройте «БД компании», введите административный токен и загрузите настройки.
2. Укажите адрес, порт, базу и пользователя, имя переменной с рабочим паролем и TLS.
   По умолчанию verify-full проверяет сертификат и имя сервера; при необходимости
   укажите путь к корневому сертификату на сервере. require шифрует соединение без
   полной проверки имени и выбирается только в соответствии с политикой компании.
3. «Проверить соединение и схему» выполняет SELECT и чтение метаданных. Таблицы не создает.
   Для проверки можно разово ввести пароль формы; при пустом поле используется окружение.
4. Если схемы или таблиц нет, разрешите их создание флажком и нажмите «Подготовить схему».
   Эта отдельная операция создает только отсутствующие объекты KUMOsystems.
   Несовместимые существующие таблицы не изменяются: для них нужна миграция.
5. «Сохранить для следующего запуска» повторно проверяет соединение с паролем именно
   из окружения, готовность таблиц и права SELECT/INSERT. Пароль формы при сохранении
   не используется. Только после успеха атомарно записывается .runtime/database.json.
6. Перезапустите API в окружении с тем же рабочим паролем. В панели проверьте активное
   хранилище. Сохраненная и активная конфигурации показаны отдельно.

Неправильный пароль, сеть, TLS или права дают обобщенную ошибку без строки подключения
и секрета. Тайм-аут соединения — 5 секунд; statement_timeout — 5 секунд,
lock_timeout — 3 секунды. DNS и несколько сетевых адресов могут увеличить общее время.

В режиме PostgreSQL старт API проверяет готовую схему, но сам не создает таблицы.
Если подключение недоступно, сервер сообщает об ошибке; скрытого переключения в SQLite нет.

## Приоритет конфигурации и возврат

Приоритет: явно заданный URL приложения → BAS_DATABASE_URL → .runtime/database.json
→ локальная SQLite. BAS_DATABASE_URL оставлен для существующего развертывания.
Если он задан, интерфейс не сохраняет другую конфигурацию, которая все равно не применится.
Уберите переменную и перезапустите API, если хотите управлять настройками через форму.

«Использовать SQLite после перезапуска» отключает сохраненную конфигурацию PostgreSQL,
оставляя ее резервную копию в .runtime/database-disabled-*.json. Записи БД не удаляются.
Если API уже не запускается из-за внешней БД, из папки backend выполните:

```powershell
# Только если переменная была задана в этом терминале:
Remove-Item Env:BAS_DATABASE_URL -ErrorAction SilentlyContinue
.\.venv\Scripts\python.exe -m bas.configure_database local
.\.venv\Scripts\python.exe -m uvicorn bas.main:app --host 127.0.0.1 --port 8000
```

Переключение не мигрирует данные. PostgreSQL покажет свои записи, SQLite — свои.
Для отдельных сценариев используйте JSON-экспорт/импорт. Массовый перенос планов и
каталога между БД еще не реализован. При переходе с раннего PostgreSQL-развертывания,
где таблицы лежали в public, их перенос в kumosystems должен выполнить администратор.

## Docker Compose и проверка

Compose для разработки теперь содержит отдельный db-init: он подготавливает схему
командой python -m bas.configure_database prepare, а API стартует после его успеха.
В этом варианте подключение задается BAS_DATABASE_URL; форма показывает этот приоритет.
Для корпоративного размещения настройте окружение, секреты и постоянный каталог
KUMO_SETTINGS_DIR согласно вашей инфраструктуре. Автоматическая миграция схемы не добавлена.

Проверены unit/API-тесты настройки, проверки прав и ошибок, сохранения без пароля и
возврата к SQLite. PostgreSQL-драйвер установлен. Реальная PostgreSQL/TLS-интеграция
в этой итерации не проверена: реквизиты компании не предоставлены, Docker Engine
недоступен. Это обязательная следующая проверка на выделенной тестовой БД компании.

Источники API: [OpenLayers XYZ](https://openlayers.org/en/latest/apidoc/module-ol_source_XYZ.html),
[SQLAlchemy PostgreSQL](https://docs.sqlalchemy.org/en/20/dialects/postgresql.html).
