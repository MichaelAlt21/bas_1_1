# Автономная сборка для Windows

Дата: 24.09.2026, версия 1.0. Закрывает требование из `DELIVERY_PLAN.md`: «запуск двойным
щелчком без отдельной установки Python/Node.js». Результат — одна папка (и ZIP-архив),
которую достаточно распаковать на 64-битной Windows 10/11 и запустить `KUMOsystems.cmd`.

## Как собрать

На машине сборки нужны подготовленные `backend\.venv` и `frontend\node_modules` (как для
разработки, см. README). Из папки `bas_1_1`:

```powershell
.\scripts\build-windows.cmd
# или: backend\.venv\Scripts\python.exe scripts\build_windows.py [--with-maptiler-key] [--skip-smoke] [--no-zip]
```

Сборка занимает около 30 с и ничего не скачивает. Результат — `dist-windows\`:
`KUMOsystems-<версия>-win64\` и ZIP-архив; для 1.1.0 — 161 МБ и 55 МБ. Папка
`dist-windows/` внесена в `.gitignore`.

## Что внутри

| Путь | Содержимое |
|---|---|
| `KUMOsystems.cmd` | Запуск: `runtime\python.exe -I -X utf8 -m bas.desktop` |
| `README.txt` | Инструкция для пользователя на русском |
| `runtime\` | Частный CPython 3.12 (из установки, на которой основан `.venv`), пакеты сервиса и код `bas` — 165 МБ до сжатия |
| `app\web\` | Собранный интерфейс (Vite), 6 МБ |
| `docs\` | Руководство оператора и история версий |
| `examples\` | Сценарии и зоны из `contracts\` |
| `data\` | Создается при первом запуске: `bas.db` (SQLite) и `.runtime` (настройки PostgreSQL) |

Пакеты берутся из `backend\.venv` строго по зависимостям `pyproject.toml` и их замыканию
(с учетом маркеров платформы), а не всем содержимым окружения: pytest, httpx и прочие
инструменты разработки в сборку не попадают. Из стандартной библиотеки исключены
tkinter, IDLE, тесты, ensurepip, venv; из numpy/shapely/pyproj — их встроенные тесты. Для
`zoneinfo` на Windows добавлен `tzdata` (новая зависимость в `pyproject.toml`).

## Запуск

`KUMOsystems.cmd` открывает окно сервера и браузер на `http://127.0.0.1:8000`. Окно —
это сервер: закрыли окно — сервер остановлен. Логика в `backend/src/bas/desktop.py`:

- Интерпретатор запускается в изолированном режиме `-I`: установленный на машине Python,
  переменные `PYTHONHOME`/`PYTHONPATH` и пользовательские пакеты не влияют на сборку.
- Порт — первый свободный из 8000–8019 (или `--port N`). Если KUMOsystems уже запущен на
  8000, второй запуск только открывает браузер.
- Данные — в `data\` рядом с `KUMOsystems.cmd`. Если туда нельзя писать (например, папка в
  Program Files), — в `%LOCALAPPDATA%\KUMOsystems\data`. Путь печатается в окне сервера.
- `--no-browser` — не открывать браузер (для проверки и автоматизации).

## Ключ MapTiler

`frontend\.env.local` содержит ключ MapTiler разработчика. По умолчанию сборка его **не
включает**: переменная `VITE_MAPTILER_KEY` задается пустой (переменные окружения важнее
`.env`-файлов Vite), а после сборки скрипт проверяет, что ключа нет ни в одном JS-файле, и
останавливается, если он там есть. Спутниковая подложка в такой сборке не настроена;
OSM, «Без подложки · офлайн» и «Мои карты» работают. `--with-maptiler-key` встраивает ключ
осознанно — тогда архив нельзя передавать за пределы команды.

## Проверки при сборке

Скрипт сам проверяет результат, прежде чем упаковать архив:

1. **Зависимости DLL**: разбирает таблицы импорта (обычные и отложенные) всех `.exe`,
   `.dll`, `.pyd` — 92 файла. Разрешены только библиотеки из сборки, `api-ms-win-*` и
   системные DLL Windows. Visual C++ Runtime копируется из System32 только если его кто-то
   импортирует (в текущей сборке не нужен — нужные `vcruntime140*.dll` идут с CPython).
2. **Байт-код** компилируется интерпретатором сборки, чтобы первый запуск был быстрым.
3. **Запуск без Python**: окружение из одних `SystemRoot`, `PATH=System32`, `TEMP` —
   импорт `bas.main`, numpy, shapely, pyproj, pydantic_core, SQLAlchemy, psycopg,
   `zoneinfo("Europe/Moscow")`, проверка, что `sys.path` и все модули лежат внутри сборки;
   затем сервер: здоровье, страница интерфейса, расчет демо-сценария и анализ парка. Тестовая
   база удаляется, `data\` в архив не попадает.

Дополнительно 24.09.2026 вручную: архив распакован в путь с кириллицей и пробелом
(`…\Проверка сборки\`), запуск через `cmd.exe` с `PATH=System32` и заведомо неверным
`PYTHONHOME` — сервер готов за 3–9 с (первый запуск дольше из-за проверки новых файлов
антивирусом), все файлы интерфейса с правильными MIME-типами, пример 201 — 16,7 мин,
несколько районов — 5,8 мин, печатный отчет, закат, повторный запуск («уже запущен»);
папка `data\` заблокирована — данные ушли в `%LOCALAPPDATA%`. Тесты `backend/tests/test_desktop.py`
(6) проверяют выбор порта, корень сборки, распознавание чужого сервиса на порту, раздачу
интерфейса из `BAS_STATIC_DIR` и оба варианта папки данных.

Сборка 1.1.0 (25.09.2026) проверена так же: распаковка в путь с кириллицей, чистое окружение,
примеры 201 (13,9 мин) и «Эшелоны» (24,1 мин), отчет, повторный запуск.

## Ограничения

- Только 64-битная Windows 10/11; сборка выполняется на Windows с тем же вариантом CPython.
- Версия Python в сборке — та, на которой основан `.venv` машины сборки (сейчас 3.12.0).
  Для сдачи лучше собрать на актуальном выпуске 3.12.x: исправления безопасности
  стандартной библиотеки попадают в сборку только так.
- `.cmd` и `python.exe` не подписаны. Файлы из архива, скачанного из интернета, Windows
  помечает; SmartScreen может предупредить — «Подробнее → Выполнить в любом случае» или
  «Свойства → Разблокировать» у архива до распаковки. Это описано в `README.txt`.
- Нет установщика, ярлыков и удаления: распаковать и запустить; удалить — удалить папку.
- Окно консоли остается открытым все время работы; скрытого фонового режима и значка в
  трее нет — осознанно, чтобы сервер нельзя было «забыть» запущенным.
- Сборка не проверялась на отдельной чистой машине — только на машине сборки с
  урезанным окружением (без Python/Node.js в `PATH`, без переменных Python).
