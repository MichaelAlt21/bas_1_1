# Типы съемки за пределами RGB

Дополнение 21.09.2026 (продолжение дня): изучены `Geoscan_801_Manual.pdf` и
`Geoscan_Gemini_Manual.pdf`, добавленные заказчиком. Gemini-мануал (с. 71) дал
второй независимый источник для Pollux (те же числа — сенсор, пиксель,
фокусное расстояние, диагональ, угол обзора — совпадают с уже использованными)
и одну новую камеру: **Sony UMC-R10C**, второй подтвержденный RGB-вариант для
Gemini наравне с PF1B (см. раздел «Камера Sony UMC-R10C» ниже). 801-мануал
(с. 87–89) подтвердил уже известные числа по обеим камерам подвеса (RGB и
тепловизор), но **не добавил** ни физический размер матрицы, ни линейный
размер пикселя ни для одной из них — только номинальный оптический формат
(1/2,3", для тепловизора вообще не указан) и фокусные расстояния. Без размера
пикселя нельзя посчитать GSD и ширину захвата, не домыслив число, поэтому 801
по-прежнему доступен только с ручной шириной захвата. Оба документа не изменили
состояние LiDAR/геофизической съемки: параметров конкретного сенсора для них
по-прежнему нет ни в одном источнике.

Дата: 21.09.2026. До этого изменения `planning/service.py` отклонял любой
`survey_type`, кроме `rgb`, кодом `SURVEY_UNSUPPORTED` — независимо от того, что
интерфейс и контракт уже допускали мультиспектральную, ИК, LiDAR и геофизическую
съемку (`docs/CAMERAS_AND_TASK_REVIEW.md` прямо фиксировал это как открытый
пункт). Задание требует поддержку всех пяти типов; `docs/DELIVERY_PLAN.md`
подтверждает решение команды держать их все в объеме. Это первый шаг: снятие
общего отказа и один полностью посчитанный по камере профиль.

## Что стало доступно

| Тип | Режим покрытия | Источник модели |
|---|---|---|
| RGB | камера (Sony RX1RM2, Geoscan PF1B, Sony UMC-R10C) или ручная ширина | UMC-R10C новое |
| Мультиспектральная | камера (Geoscan Pollux) или ручная ширина | новое |
| ИК | только ручная ширина | новое |
| LiDAR | только ручная ширина | новое |
| Геофизическая | только ручная ширина | новое |

Нагрузка каждого борта (`aircraft.payload`) должна совпадать с `survey_type`
сценария — это одна операция с одним типом работ, как и было для RGB, только
проверка теперь сравнивается с фактическим типом, а не жестко с `rgb`
(`PAYLOAD_MISMATCH`). В интерфейсе смена типа съемки на вкладке «Съемка»
переназначает нагрузку всего парка и сбрасывает выбранные камеры бортов —
без этого старые борта с нагрузкой `rgb` не прошли бы новую проверку.

## Камера Geoscan Pollux

`catalog/cameras.py` получил профиль `geoscan_pollux_v1`: разрешение
1440×1080, пиксель 3,45 мкм (отсюда матрица 4,968×3,726 мм), фокусное
расстояние 8 мм. Источник — `Gemini_Specs.pdf`, с. 3–4 (данные о камере Pollux
продолжаются на следующей странице листа характеристик) и
`Geoscan_201_Manual.pdf`, с. 117 (объектив 8 мм для Pollux на 201). Размер
матрицы посчитан из пикселя и разрешения, тем же способом, что и для PF1B/RX1RM2,
а не взят из округленного обозначения «1/2,9 дюйма»; расчет сверен с
собственными диагональю (6,3 мм) и углом обзора (43°) листа характеристик —
совпадение с точностью до округления подтверждает физическую согласованность.
Профиль совместим с Gemini и Геоскан 201 (оба упомянуты производителем как
носители Pollux). Захват, GSD и продольное перекрытие считаются той же
геометрией, что и для RGB-камер, — **это только геометрия кадра, не обработка
спектральных каналов**: регистрация полос, радиометрическая калибровка и
вегетационные индексы в расчет не входят.

## Камера Sony UMC-R10C

`catalog/cameras.py` получил второй подтвержденный RGB-профиль для Gemini:
`sony_umc_r10c_v1` — разрешение 5456×3632 (20,1 Мп), матрица APS-C 23,2×15,4 мм,
фокусное расстояние 20 мм (тот же объектив, что и у PF1B), механический
шторно-щелевой затвор, диафрагма f/2,8. Источник — `Geoscan_Gemini_Manual.pdf`,
с. 71, таблица «Фотокамера Geoscan PF1B/Sony UMC-R10C»: числа PF1B в этой же
таблице совпадают с уже использованными в каталоге (6000×4000, APS-C
23,5×15,6 мм) — независимое подтверждение того, что извлечение таблицы из
двухколоночной верстки не перепутало столбцы. `Gemini_Specs.pdf` упоминает
UMC-R10C по имени как альтернативу Pollux на том же подвесе, но не дает ее
числовые характеристики — они есть только в мануале.

## ИК, LiDAR, геофизическая съемка: ручная ширина

Подтвержденного профиля сенсора для этих трех типов пока нет:

- ИК: в руководстве 801 указаны только разрешение (640×512) и фокусное
  расстояние тепловизионного объектива (9,1 мм); размер пикселя матрицы не
  подтвержден, поэтому геометрию кадра посчитать нельзя без домысливания.
- LiDAR и геофизическая (например, магнитометрическая) съемка — не камеры:
  их «ширина захвата» — это полоса сканирования или шаг линий, параметр
  конкретного прибора и методики, а не что-то выводимое из фокусного
  расстояния и матрицы. В компанию не предоставлены характеристики
  конкретного сканера/магнитометра.

Для всех трех включен путь `coverage_mode='manual'`, уже существовавший для
RGB: оператор задает ширину полосы (10–500 м), и та же геометрия покрытия
(буфер вдоль галсов) применяется к ней без изменений — модель покрытия
рассматривает сенсор как метущий коридор заданной ширины, что подходит для
сканирующих/буксируемых приборов не хуже, чем для приближения фотокамеры.
Явные предупреждения плана называют тип съемки и то, что именно не проверено
(GSD/тепловое разрешение для ИК; плотность точек и угол обзора для LiDAR;
чувствительность и высота буксировки для геофизической). Камерный режим
(`coverage_mode='camera'`) для этих трех типов отклоняется кодом
`SURVEY_UNSUPPORTED` — камеры без подтвержденного профиля не подставляются
как приближение, ошибка возвращается явно.

## Ограничения

- Только геометрическое покрытие; ни один из пяти типов не подтверждает
  качество данных конкретного метода съемки.
- Мультиспектральная модель — геометрия Pollux, не обработка каналов.
- ИК/LiDAR/геофизическая — оператор сам определяет ширину; она не выводится
  из паспортных характеристик, потому что таких данных в компании пока нет.
- Совместимость Pollux ограничена Gemini и 201; для 801 в любом типе съемки
  камерный режим недоступен, только ручная ширина.

## Проверено

`backend/tests/test_cameras_fixedwing.py`: геометрия Pollux по пиксельным
размерам, геометрия UMC-R10C, отказ при несовпадении `sensor_type` камеры и
нагрузки борта. `backend/tests/test_planning.py`: полный расчет для
мультиспектральной, ИК, LiDAR и геофизической съемки с ручной шириной и
характерным предупреждением; отказ при несовпадении нагрузки борта и типа
съемки операции; отказ камерного режима для LiDAR кодом `SURVEY_UNSUPPORTED`;
расчет по новому примеру `contracts/scenario.multispectral.example.json`.
Каталог камер отдает четыре профиля. В браузере: переключение демо-сценария
на мультиспектральную съемку с автоподстановкой Pollux и корректным расчетом
(GSD 4,31 см/пикс, захват 62,1 м — совпадает с ручным расчетом); отказ
несовместимого борта 801 до его удаления из парка; переключение на LiDAR
скрывает пункт «По камерам» и считает с ручной шириной; выбор UMC-R10C для
Gemini дает GSD 2,13 см/пикс и захват 116,0 м, совпадающие с ручным расчетом,
и успешный расчет плана. ИК и геофизическая съемка проверены только тестами.
