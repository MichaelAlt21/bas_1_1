# Один процесс и запуск одним файлом

Дата: 21.09.2026. `DELIVERY_PLAN.md` называет требование заказчика явно:
«Требуется запуск двойным щелчком без отдельной установки Python/Node.js» —
и отмечает его как нереализованное. Это первый шаг к нему: один серверный
процесс отдает и API, и собранный интерфейс, плюс Windows-скрипт, который
запускает этот процесс и открывает браузер.

## Что сделано

`backend/src/bas/main.py`: `create_app()` получил параметр `static_dir`
(по умолчанию — `frontend/dist` рядом с проектом, вычисляется от `__file__`,
без опоры на текущий рабочий каталог). Если каталог существует, он
монтируется в FastAPI как `StaticFiles(html=True)` на `/`, **после** всех
`/api/...` маршрутов — точный порядок операций важен: Starlette проверяет
маршруты в порядке регистрации, поэтому смонтированный каталог не может
перехватить `/api/...`, только незанятые пути вроде `/` и `/assets/...`.
Если `frontend/dist` не собран (обычная разработка через Vite), монтирование
просто не происходит и поведение не меняется.

`run.bat` в корне `bas_1_1` вызывает `scripts/run.ps1` через
`powershell -ExecutionPolicy Bypass`, в обход политики выполнения, которая на
чистой Windows обычно блокирует локальные `.ps1` без такого флага. Сам
`run.ps1`: проверяет `backend/.venv`, при отсутствии `frontend/dist/index.html`
собирает frontend (`npm ci` при отсутствии `node_modules`, затем
`npm run build`), открывает браузер на `http://127.0.0.1:8000` и запускает
`uvicorn` без `--reload` из `.venv`. Требует уже подготовленных `.venv` и
(при первой сборке) `npm`/интернет — это не автономный установщик, Python и
Node.js на машине по-прежнему нужны на этапе подготовки.

## Найденный попутно баг: `.js` как `text/plain`

Проверка запуска через один процесс (а не через прежний Vite-прокси) сразу
показала реальную проблему: браузер отказывался выполнять собранный модуль
с ошибкой `Expected a JavaScript-or-Wasm module script but the server
responded with a MIME type of "text/plain"`. Starlette определяет тип файла
через `mimetypes.guess_type()`, а тот на Windows подмешивает записи реестра
(`HKEY_CLASSES_ROOT\.js`) поверх встроенных значений; на машине, где
собирался и проверялся этот проект, реестр отдавал `text/plain` для `.js`.
Без принудительного `mimetypes.add_type('application/javascript', '.js')`
(и `.mjs` на всякий случай) перед монтированием статики запуск одним
процессом выглядел бы рабочим в тестах (они не проверяли реальный заголовок
до этого дня), но ломался бы в браузере на конкретных Windows-машинах —
ровно в сценарии, для которого и делался запуск одним файлом. Это уже
проверено тестом (`test_built_frontend_is_served_without_shadowing_the_api`
в `test_api.py`) с явной сборкой `.js` через `StaticFiles`, а не только
проверкой `/`.

При проверке в браузере пойман еще один нюанс: после первой (специально
сломанной для теста) загрузки браузер закешировал `.js` с неверным
заголовком по тому же versioned-имени файла, и обычная перезагрузка страницы
эту запись не обновляла — только запрос с обходом кеша показывал
исправленный заголовок. В реальном использовании это не повторится: у
реальных пользователей нет предыдущей «сломанной» записи в кеше для этого
конкретного собранного файла, а у Vite каждая новая сборка меняет имя файла
по хешу содержимого.

## Ограничения

- Не автономная сборка: `.venv` и (при первой сборке frontend) `npm` должны
  быть на машине заранее. Запуск без Python/Node.js сделан 24.09.2026 отдельно —
  [WINDOWS_STANDALONE.md](WINDOWS_STANDALONE.md); `run.bat` остается запуском из исходников.
- `run.bat`/`run.ps1` не проверялись на чистой Windows-машине без уже
  настроенного окружения разработки — только в среде, где `.venv` и
  `node_modules` уже существовали.
- `uvicorn` без `--reload`: изменения backend-кода требуют перезапуска
  скрипта, как и полагается для рабочего (не dev) запуска.
- Собранный frontend отдается как обычные статические файлы, без отдельной
  политики кеширования сверх заголовков Starlette по умолчанию.

## Проверено

102 серверных теста проходят (два новых: собранный frontend отдается без
перекрытия `/api/...`, а его `.js` — с корректным `Content-Type`; и что
отсутствие сборки не ломает API). Регрессионный тест намеренно проверен:
без `mimetypes.add_type` тест `test_built_frontend_is_served_without_shadowing_the_api`
падает на заголовке `.js` — то есть он действительно ловит эту ошибку, а не
проходит случайно.

В браузере: `curl`/`fetch` с обходом кеша подтвердили `Content-Type:
application/javascript` после исправления и то, что `/`, `/assets/...` и
`/api/health` отвечают из одного процесса на порту 8000. Полный пользовательский
сценарий (карта → сценарий → расчет) в этом однопроцессном режиме отдельно не
пройден: он уже проверялся ранее через Vite-прокси, который использует тот же
frontend-код и тот же `/api`-контракт, поэтому не создает дополнительного риска
здесь. `run.bat` целиком (включая диалог `pause` и открытие системного браузера)
не запускался в этой сессии — так как это привело бы к обращению к обычной,
неконтролируемой сессией браузера машины пользователя; логика скрипта проверена
чтением, а запускаемые им команды (сборка frontend, `uvicorn`, монтирование
статики) проверены по отдельности.
