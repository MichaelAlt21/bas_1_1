# История архитектурных решений (версии 0.1–1.1)

Записи, которые команда вела по мере разработки, от новых к старым. Актуальное описание — [ARCHITECTURE.md](ARCHITECTURE.md). Таблицы API и файлов ниже могут быть устаревшими.

## Версия 1.1

Версия 1.1, 25.09.2026. `planning/service.py::plan` проверяет входные данные и вызывает
`_attempt` (геометрия, парк, распределение, расписание) с высотой каждого борта; при
эшелонах `planning/echelons.py` по первому плану назначает уровни, `_relevel` пересчитывает те
же маршруты коптеров на новых высотах и расписание, `_post_processing` собирает предупреждения
и ответ. `scheduling/conflicts.py` разводит по высоте (линейно во времени) и находит
минимальную задержку старта. `flight_models/dubins.py` — шесть слов Дубинса, метод
виртуальной цели в ветре, выборка трохоид; `fixed_wing.py` — соединения с заходом на галс,
спиральный набор, снижение перед выпуском парашюта; `catalog/cameras.py` — полоса кадра при
сносе. Для самолета в распределении `insert` вставляет галс в лучшее место вылета, `improve`
дорабатывает порядок. [Описание](ECHELONS_AND_FIXED_WING.md).

## Взаимодействие

1. React показывает редактор и фотографии из frontend/public/aircraft.
2. OpenLayers получает тайлы OSM/MapTiler. Геометрия сценария хранится отдельно.
3. Карта отображается в EPSG:3857, в API передаются GeoJSON-координаты WGS84:
   сначала долгота, затем широта. Смена подложки координаты не меняет.
4. FastAPI валидирует Scenario через Pydantic и Shapely и сохраняет снимок с UUID.
5. Запрос расчета загружает снимок и синхронно вызывает planning/service.py.
6. Ядро переводит геометрию в локальные метры, строит покрытие, распределяет галсы,
   рассчитывает время, разводит конфликты и проверяет результат.
7. План сохраняется отдельным JSON в БД. UI рисует маршруты, показатели и расписание.
8. Экспорт строится из сохраненного плана, без повторного расчета.

Обычная def-функция FastAPI выполняется в пуле потоков. Очередь, worker, прогресс
и отмена еще не реализованы. UI блокирует изменение сценария во время запроса.
Для сравнения сохраняются два снимка с разными критериями и выполняются два расчета.

## Хранение

SQLAlchemy хранит JSON в таблицах scenarios и plans. Локально SQLite; в Compose
PostgreSQL/PostGIS, но пространственный SQL пока не используется.
Снимки неизменяемые: повторное сохранение создает новый UUID. Список показывает последние
50 снимков. План ссылается на UUID исходного сценария.

create_all добавляет отсутствующую таблицу plans, не изменяя существующую scenarios.
Для изменений столбцов нужны миграции Alembic. schema_version сценария остается 0.1:
новые поля имеют значения по умолчанию. Старый снимок открывается, но для расчета может
потребовать назначения стартов и разрешенного пространства.

План содержит этапы с временем от начала операции, координатами, высотами AGL,
воздушной скоростью горизонтального движения и вертикальной скоростью.
При экспорте отдельного аппарата metrics остаются показателями всей операции.
