# Сдача KUMOsystems: решения команды и план на восемь дней

Зафиксировано 21.09.2026 по ответам команды. Это план работ, а не обещание уже готовых функций.
Срок: через восемь дней, вместе с презентацией и документацией. Точный час сдачи и длительность выступления неизвестны; ниже используются относительные дни.

## Принятые требования

| Вопрос | Решение / статус |
|---|---|
| Типы работ | Все пять из задания остаются в объеме: RGB, мультиспектральная, ИК, LiDAR, геофизическая. Поддержка должна иметь расчетный смысл; наличие пункта меню не считается реализацией |
| Размер операции | Реальные площади и расстояния неизвестны. Текущий лимит пяти БПЛА — ограничение прототипа, не требование заказчика |
| Распределение | Рабочее допущение команды: одну зону можно делить между аппаратами; один аппарат может снимать несколько зон |
| Горизонт планирования | Один вылет на аппарат; повторные вылеты, зарядка и замена батарей пока вне объема |
| Посадка | Допускается другая подходящая основная площадка. Резервные площадки предназначены для аварийных ситуаций |
| Геоскан 201 | Обязателен и должен участвовать в расчетах. Допускается демонстрационная модель с явно обозначенными допущениями |
| Камеры, GSD, перекрытия | Фактическая комплектация и требования к качеству не подтверждены. Использовать именованные профили из исследования и настраиваемые значения |
| Экспорт | KML/GeoJSON по заданию. Целевая программа и формат загрузки в автопилот неизвестны; совместимость с автопилотом не заявлять |
| Сдаваемая сборка | Целевая ОС — предположительно Windows. Требуется запуск двойным щелчком без отдельной установки Python/Node.js. Наличие интернета на защите пока не подтверждено |
| Визуал | Сохранить стиль до уточнений. Исправить перекрытие карты подсказкой и добавить удобную отмену |
| Команда | Один участник проверяет код и работает с ассистентом; остальные пока разрабатывают идеи. Распределение задач ниже — предложение |

## Последовательность завершения

| День | Основной результат | Проверка готовности |
|---|---|---|
| 1 | Удобное редактирование, фиксация объема, начало профилей камер | Отмена/повтор зон, отмена вершины; источники параметров указаны |
| 2 | Расчет RGB по камерам и демонстрационная модель 201 | Захват связан с высотой/камерой; самолет не разворачивается мгновенно и не зависает |
| 3 | Смешанный парк, выбор посадки, резервные площадки | Разные характеристики аппаратов влияют на назначение; возвращение и запас ресурса проверяются |
| 4 | Модели остальных видов съемки | Для каждого режима определены совместимая нагрузка, параметры и критерий покрытия; неизвестные значения обозначены |
| 5 | Первый комплект для сдачи | Рабочая Windows-сборка, черновик презентации, руководство, архитектура, API и ограничения |
| 6 | Сквозные сценарии и исправления | Два критерия, несколько зон/площадок, смешанный парк, экспорт, ошибочные входные данные |
| 7 | Заморозка функций и репетиция | Сборка запускается на другом ПК; презентация соответствует реально работающей версии |
| 8 | Резерв и сдача | Финальный архив, исходники, документация, презентация, демонстрационные данные и резервная запись демо |

Это целевой порядок. Наибольший риск — самолетная геометрия и неподтвержденные нагрузки, особенно LiDAR и геофизика. Для таких режимов нельзя выдавать произвольную ширину полосы за подтвержденное качество данных. Допустим параметрический демонстратор с явно заданными параметрами сенсора/шага линий и ограничениями результата. Если расчет режима не реализован, он остается открытым пунктом приемки.

автоматически, потолок 150 м) и разведение по высоте; модель 201 доработана без данных
заказчика — все параметры, которые он мог бы подтвердить, настраиваются.
[ECHELONS_AND_FIXED_WING.md](ECHELONS_AND_FIXED_WING.md).

Обновление 24.09.2026, автономная сборка: пункт «Сдаваемая сборка» закрыт — ZIP для
64-битной Windows с собственным Python, двойной щелчок по `KUMOsystems.cmd`, без
установки Python/Node.js и без интернета (кроме подложки карты).
[WINDOWS_STANDALONE.md](WINDOWS_STANDALONE.md). Остается проверить на машине, где пройдет
защита.

Обновление 24.09.2026, версия 1.0 — выпуск для сдачи: из пунктов «Сдаваемая сборка» закрыта
работа без интернета (подложка «Без подложки»); автономный установщик без Python/Node.js
остается открытым. Добавлены темная тема, руководство оператора
([USER_GUIDE.md](USER_GUIDE.md)) и история версий ([CHANGELOG.md](../CHANGELOG.md)).

Обновление 24.09.2026, версия 0.9: зарядка и смена АКБ, остававшиеся вне объема,
смоделированы: «Замена АКБ» (запасная заряженная) или «Зарядка на площадке» с числом ЗУ на
каждой площадке, включая запасные, и очередью к ЗУ. Интерфейс переведен в цвета заказчика.
[Результат и ограничения](UI_AND_CHARGING.md).

Обновление 23.09.2026, версия 0.8: по материалам и ответам заказчика изменились две
строки таблицы. «Размер операции» — теперь известен: пример задания 245 км²,
около 560 вылетов Gemini; он оценивается целиком и планируется пакетами.
«Горизонт планирования» — допущение «один вылет на аппарат» снято: повторные вылеты
с подготовкой между ними, срок работ, лимит бортов и «до заката» реализованы, а
анализ парка отвечает на вопрос заказчика «сколько дронов нужно к сроку / сколько
займет работа с заданным числом». Зарядка и смена АКБ по-прежнему не моделируются.
[Результат и ограничения](AIRSPACE_AND_CUSTOMER_DATA.md).

Обновление 22.09.2026, версия 0.7: пункт «Посадка» из таблицы принятых требований
реализован — борт может сесть на другую подходящую основную площадку, для самолета
с проверкой линии сноса парашюта; резервные площадки по-прежнему только для
аварийной оценки. Включается настройкой, по умолчанию поведение прежнее.
[Результат и ограничения](LANDING_SITES.md). Из «Границ» ниже остаются открытыми
автономная Windows-сборка без Python/Node.js, работа демо без интернета (подложка
карты) и пригодность самих резервных площадок.

Обновление 21.09.2026: первый шаг к запуску двойным щелчком — API само отдает
собранный frontend, `run.bat` запускает один процесс и открывает браузер, без
отдельного Vite. [Результат и ограничения](SINGLE_PROCESS_LAUNCH.md). Это не
автономный установщик: `.venv` (Python) и `npm ci` (Node.js) по-прежнему нужно
подготовить на машине заранее, разово. Полностью самодостаточная сборка без
установленных Python/Node.js остается следующим шагом.

Обновление 21.09.2026: все пять типов съемки из задания теперь принимаются расчетом
вместо общего отказа вне RGB. Мультиспектральная считается по подтвержденному профилю
камеры Geoscan Pollux — той же геометрией, что и RGB-камеры. ИК, LiDAR и геофизическая
принимаются с шириной захвата, заданной оператором, поскольку подтвержденных параметров
конкретного сенсора (тепловизор 801, сканер, магнитометр) в компании пока нет.
[Результат и ограничения](SURVEY_TYPES.md). Наличие пункта меню и реальный расчет теперь
не расходятся: любой выбранный тип действительно участвует в планировании, а не
отклоняется на входе. Обработка спектральных/тепловых/сканирующих данных, реальные
параметры LiDAR и магнитометра остаются вне объема этой сдачи.

Обновление 21.09.2026: достижимость резервных площадок теперь проверяется
в самой удаленной точке маршрута каждого борта (кратчайший путь в свободном
пространстве против оставшегося бюджета времени), как информационная оценка,
не блокирующая план. [Результат и ограничения](RESERVE_SITES.md). Сама резервная
площадка пока не проверяется на пригодность посадки, и план не перепланирует
посадку на резерв — это остается следующей задачей вместе с выбором другой
основной площадки.

Обновление 21.09.2026: расчет RGB по двум профилям камер, демонстрационный 201
и индивидуальные скорости смешанного парка реализованы.
[Результат и ограничения](CAMERAS_AND_FIXED_WING.md). Выбор другой основной площадки
посадки, остальные четыре режима и Windows-сборка остаются
следующими задачами; план работ не означает их готовность.

- Планировщик назначает каждому борту часть работы, начало и конец единственного вылета. Невыбранные аппараты могут оставаться на земле, если это улучшает критерий.
- Разделять площадку базирования, выбранную основную посадку и аварийные альтернативы.
- Подходящая площадка должна учитывать тип аппарата, геометрию запуска/посадки и достижимость с остатком ресурса; одной точки на карте для самолета недостаточно.
- Профиль камеры хранится отдельно от БПЛА; его версия, источник и допущения сохраняются с планом.
- Поддержка мультиспектральной/ИК-съемки означает расчет задания для соответствующей нагрузки. Обработка снимков и создание конечных геопродуктов не входят в это понятие автоматически.
- Симуляция показывает выполнение плана; реальная телеметрия не включена в текущую сдачу.
- Windows-сборка должна включать необходимые компоненты. Онлайн-подложки и погода зависят от сети; резервный сценарий должен работать без погодного API и без обязательной загрузки тайлов. Это еще предстоит реализовать/проверить.

## Что команда может готовить уже сейчас

1. Сюжет защиты: проблема → входные данные → распределение → сравнение двух критериев → экспорт → ограничения и развитие. Слайды с результатами заполнять из окончательных расчетов.
2. Один основной пример и один пример ошибки: несколько зон и площадок; отдельно недостаточный заряд или непроходимая запретная зона.
3. Проверка на другом Windows-ПК и перечень неудобств. Подготовить резервную запись демонстрации после стабилизации версии.
