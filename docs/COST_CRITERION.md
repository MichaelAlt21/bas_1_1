# Третий критерий: стоимость J = α·T + cᵀt + tᵀQt

Версия 1.2 (17.10.2026). Код: `backend/src/bas/planning/cost.py` (формула, проверка, разложение,
компромисс), `backend/src/bas/catalog/costs.py` (коэффициенты по открытым данным), поиск —
`backend/src/bas/planning/service.py` (`local_search`, общий для трех критериев), интерфейс —
раздел «Параметры → Модель стоимости J», переключатель «Стоимость» и график компромисса в сравнении.

## 1. Формула и обозначения

```
J = α·T + cᵀt + tᵀQt = α·T + Σ_i c_i·t_i + Σ_i q_ii·t_i² + 2·Σ_{i<j} q_ij·t_i·t_j
```

| Символ | Смысл | Единица |
|---|---|---|
| T | время завершения операции: от первого взлета до посадки последнего борта (makespan) | ч |
| t_i | налет борта i — сумма времени в воздухе за все его вылеты | ч |
| L = Σ t_i | суммарный налет парка (критерий «Меньше налет») | ч |
| α | цена часа срока операции (бригада, транспорт) | у.е./ч |
| c_i | цена часа налета борта i (риск потери борта, ресурс АКБ) | у.е./ч |
| q_ii | индивидуальный квадратичный коэффициент борта i | у.е./ч² |
| q_ij = q_ji | парный коэффициент бортов i и j | у.е./ч² |
| J | условная стоимость операции | у.е. |

**у.е. — условные единицы стоимости.** Коэффициенты по умолчанию оценены по открытым данным (§3):
в них 1 у.е. ≈ 1 ₽ в ценах 2025–2026, но это оценка, а не данные заказчика и не бухгалтерский расчет.

Что входит в t_i: только полет (взлет, набор, перелеты, съемка, возвращение, посадка). Ожидание
старта, замена АКБ, зарядка, очередь к ЗУ и смена нагрузки — время на земле, в t_i не входят, но
удлиняют T.

**Множитель 2.** Q симметрична, поэтому в tᵀQt пара (i, j) встречается дважды: q_ij·t_i·t_j и
q_ji·t_j·t_i. Пара задается один раз и входит в J как 2·q_ij·t_i·t_j.

**t_i·t_j — произведение длительностей**, а не время совместного полета.

**«Квадрат стоимости налета».** Возвести в квадрат стоимость налета (руб.²) нельзя: J должна
оставаться стоимостью. Квадратичная часть строится из квадрата *времени* (ч²) с коэффициентом в
у.е./ч²: q·t² — уже стоимость; предельная цена часа налета борта равна c_i + 2·q_ii·t_i.

### Почему в формуле есть cᵀt (изменение 17.10.2026)

Первая версия критерия была J = α·T + tᵀQt с весами α = 60 у.е./ч и q = 30 у.е./ч². На
реальных масштабах она вырождалась: при t_i ≈ 0,15–1 ч величина t_i² мала (0,02–1 ч²), и J ≈ α·T —
план J совпадал с планом «Быстрее завершить» (замечание заказчика по примеру «коптеры»: J 10,8 у.е.,
из них α·T 9,4). Квадратичная форма без линейной части к тому же утверждает, что первые минуты
полета почти бесплатны (предельная цена 2q·t → 0 при t → 0), что экономически неверно: у каждого
часа налета есть цена — износ, ресурс АКБ, риск потери борта.

Поэтому J дополнена линейным вектором c — это общий вид линейно-квадратичной функции
(линейная часть + квадратичная форма). Теперь J — компромисс: α·T — цена срока, cᵀt — цена
налета; чем дороже час налета относительно часа срока, тем выгоднее летать меньше, а не
закончить быстрее. Заодно снят вопрос «T или L в линейной части»: обе величины входят со своими
ценами — срок с α, налет каждого борта с c_i. Модели, сохраненные без c, считаются с c = 0, то
есть по исходной формуле.

## 2. Проверки и особые случаи

Нормировка фиксирована: время в часах, коэффициенты в у.е./ч и у.е./ч². Проверки (сервер
`validate_cost_model`, интерфейс — та же логика в `features/scenarios/requirements.ts`):

- α ≥ 0, c_i ≥ 0, q_ii ≥ 0, все числа конечные;
- пара не может связывать борт с самим собой и задаваться дважды (в любом порядке);
- коэффициенты ссылаются только на борта парка (по бортовым номерам);
- Q положительно полуопределена: наименьшее собственное значение ≥ −10⁻⁹·max|q|. Для одной пары
  достаточно q_ij² ≤ q_ii·q_jj, для всей матрицы — только проверка целиком (три пары по −0,6 при
  q_ii = 1: каждая пара проходит, матрица — нет).

PSD гарантирует tᵀQt ≥ 0 при любых t. Особые случаи: α = 0 — срок не стоит ничего; c = 0 и Q = 0 —
J = α·T, то есть «Быстрее завершить»; неиспользованный борт (t_i = 0) ничего не добавляет;
повторные вылеты суммируются в t_i.

**Коэффициенты по типам бортов.** c и q можно задать для типа (модели БПЛА, `by_profile`): значение
действует на все борта этого типа без своего значения. Порядок: свое значение борта → значение
типа → значение по умолчанию; проверка Q на полуопределенность выполняется по итоговым значениям.
Пресет открытых данных заполняется именно по типам.

Коэффициенты хранятся по бортовым номерам: перестановка бортов не меняет J, переименование
переносит коэффициенты, удаление борта удаляет его коэффициенты и пары, сервер отвергает модель
со ссылкой на отсутствующий борт. Интерфейс не показывает матрицу 20×20: три главных веса (α,
c и q по умолчанию), по запросу — таблица типов бортов, таблица отдельных бортов (c_i, q_ii) и список пар.

копирует их в сценарий для правки. Статусы: **подтверждено** — документ производителя, прайс,
закон; **вычислено** — по формуле из подтвержденных величин; **допущение** — данных не нашлось.

| Паспортная длительность полета | 40 мин | 180 мин | 40 мин | каталог профилей (руководства) |

Перекрестная проверка c по рынку страхования: КАСКО БВС — 6–16% стоимости в год (обзор
ComNews, 2024); при 200 летных часах в год это 480–1 280 ₽/ч для Gemini — тот же порядок, что
λ × цена = 1 600 ₽/ч.

**q_ii — риск повторного облета.** Если борт откажет после τ из своих t_i часов, оставшиеся
t_i − τ часов его работы облетают другие, и операция длится дольше. Ожидаемая цена:
∫₀^{t_i} λ·(α + c_i)·(t_i − τ) dτ = λ·(α + c_i)·t_i²/2, откуда **q_ii = λ·(α + c_i)/2** — 2,19 (Gemini),
2,66 (201), 2,95 (801) у.е./ч². Пары по умолчанию 0.

Вывод из чисел: **квадратичная часть по открытым данным мала** — при t = 1 ч q·t² ≈ 2 у.е. против
c·t ≈ 1 900 у.е. Это честный результат калибровки: риск концентрации работы на одном борту
вторичен по сравнению с ценой срока и налета. Квадратичная часть остается инструментом оператора:
поднять q борта, который близок к ТО (ограничить его налет), задать q_ij для бортов с общим
пилотом или зарядным местом.

## 4. Экономический смысл трех критериев

| Критерий | Минимизирует | Когда уместен |
|---|---|---|
| Быстрее завершить | T | окно работ ограничено (погода, свет, допуск на объект) |
| Меньше налет | L = Σ t_i | ресурс бортов и АКБ дороже времени бригады |
| Минимум стоимости | J = α·T + cᵀt + tᵀQt | нужен денежный компромисс между сроком и налетом разных бортов |

**Почему план J может совпасть с одним из двух других.** Без квадратичной части J — взвешенная
сумма срока и цены налета. Такая сумма выбирает вариант на нижней выпуклой оболочке множества
точек (T, цена налета): если между планом «Быстрее» и планом «Меньше налет» нет промежуточного
варианта на этой оболочке, J совпадет с одним из них — и это правильный ответ при этих ценах.
График «срок — стоимость налета» в сравнении показывает все найденные варианты, выбор каждого
критерия и **диапазон α, при котором J выбирает каждый вариант** (точки излома оболочки):
вариант k выгоден, пока (F_k − F_{k+1})/(T_{k+1} − T_k) ≤ α ≤ (F_{k−1} − F_k)/(T_k − T_{k−1}), где F —
цена налета cᵀt + tᵀQt.

Примеры с коэффициентами по открытым данным (T и L — мин, J — у.е.):

| Сценарий | «Быстрее» T · L · J | «Меньше налет» T · L · J | «Стоимость» T · L · J | Пояснение |
|---|---|---|---|---|
| Пример: коптеры (Gemini + 801) | 9,4 · 18,7 · 1 214 | 14,0 · 14,0 · 1 023 | 14,0 · 14,0 · 1 023 | час 801 дороже (3 400 против 1 890); поднимать его ради 4,6 мин выгодно, только если α ≥ 4 960 у.е./ч |
| Пример: виды съемки | 66,5 · 122,7 · 7 378 | 105,2 · 120,4 · 8 912 | 66,5 · 122,7 · 7 378 | налет почти не зависит от плана (съемка занимает большую часть), срок — сильно; при α 83–607 J выбрал бы промежуточный вариант 68,7 мин, ниже 83 — «Меньше налет» |
| Пример: 201 + Gemini | 13,2 · 24,6 · 1 529 | 17,8 · 17,8 · 1 579 | 13,2 · 24,6 · 1 529 | второй борт окупается сроком |
| Пример: эшелоны (8 Gemini) | 23,5 · 152,3 · 5 774 | 23,6 · 133,8 · 5 197 | 23,6 · 133,8 · 5 197 | 7-й борт сокращает срок на 0,1 мин, а налет растет на 18 мин |

Что является допущением: квадратичная форма, значения коэффициентов, отсутствие платы за каждый
вылет (цикл АКБ пересчитан в час налета) и за задействование борта. Что нужно от заказчика:
фактическая стоимость часа бригады и транспорта, цены и ресурс бортов и АКБ, статистика отказов,
нормативы ТО.

## 5. Поиск плана и согласованность трех критериев

Ограничения не ослабляются: заряд и резерв, покрытие каждого требования, разрешенное пространство,
зоны и препятствия, частота съемки, разведение бортов, ЗУ и смены нагрузки проверяются одинаково
для всех критериев. Разделение ролей:

- **допустимость** — построение маршрутов и расписания (`realize`, проверка бюджета, расписание);
- **целевая функция** — T, L или `cost.breakdown` на итоговом расписании;
- **поиск кандидатов** — шаги ниже.

1. *Распределение.* Для каждого направления галсов полосы распределяются жадной вставкой по
   трем политикам: минимум загрузки самого занятого борта, минимум налета и минимум приращения ΔJ
   (оценка `cost.estimator` по текущим t_i и сроку вылетов). Это кандидаты.
2. *Локальный поиск* (`local_search`) — **один и тот же для всех трех критериев**, с одним
   бюджетом, отличается только ключ сравнения: T → (T, L); L → (L, T); J → (J, Σ t_i²).
   Ходы: перенос полосы в другой вылет (relocate), обмен полос между вылетами (swap, до 40 полос),
   «роспуск» последнего вылета борта. Каждый ход сначала грубо оценивается, лучшие
   пересчитываются точно, с маршрутами и расписанием; принимается только допустимый план со строго
   меньшим ключом. Старты: T и L — от лучшего по своему ключу кандидата, не зависящего от модели
   стоимости (без политики ΔJ); J — от лучшего по J кандидата. Второй проход: если лучший по
   какому-то ключу план нашел поиск другого критерия, поиск этого критерия продолжается от него.
3. *Общий набор планов.* Кандидаты и итоги трех поисков образуют один набор; каждая цель берет
   из него лучший план по своему ключу. Поэтому для одного сценария **план «Быстрее» не хуже двух
   других по T, «Меньше налет» — по L, «Стоимость» — по J** (тест
   `test_each_criterion_is_best_by_its_own_measure`). J — баланс: его план не короче плана
   «Быстрее» и не экономнее по налету плана «Меньше налет»; при малом q относительно α он может
   совпасть с планом «Быстрее».
4. *Бюджет:* до 4000 проверок ходов и 30 точных пересчетов на каждый поиск; исчерпание видно в
   результате.
5. *Воспроизводимость:* без случайности; одинаковые входные данные дают одинаковый план.

Следствие общего набора: план «Быстрее» или «Меньше налет» может измениться при изменении
коэффициентов J — поиск по J иногда находит более короткий или более экономный план, и тогда он
становится планом своего критерия (в предупреждениях плана сказано, каким поиском он найден).
Хуже результата поиска своего критерия от не зависящего от J старта такой план не становится.
Точный минимум T от q, конечно, не зависит: зависимость — свойство эвристики.

Почему так сделано. Раньше (до 17.10.2026) локальный поиск выполнялся только для J, а «Быстрее» и
«Меньше налет» считались жадной эвристикой без него — ради побитовой воспроизводимости 1.1. На
примерах план J получался короче плана «Быстрее» (1,01 ч против 1,11 ч на «виды съемки»), что
противоречит смыслу критериев: J — баланс между T и L. Теперь поиск одинаков для всех, а общий
набор планов исключает такие противоречия для любого сценария.

Эшелоны: второй проход с разведением по высоте принимается, если ухудшает показатель своего
критерия не больше чем на 5% (ради безопасности). С эшелонами гарантия «не хуже по своему
показателю» действует с этой оговоркой.

Анализ парка (таблица «1, 2, 3 … бортов») считает планы без локального поиска — иначе он занимал
бы минуты; его строки — оценка сверху плана, который строит кнопка «План».

Глобальный минимум не гарантируется: задача включает распределение полос (обобщение задачи о
назначениях с квадратичной целью, NP-трудно) и маршрутизацию.

## 6. Источники

Источники обосновывают структуру критерия и метод, а не значения коэффициентов. LQR
(линейно-квадратичный регулятор) здесь ни при чем: tᵀQt — квадратичная форма от итоговых
налетов, а не интеграл по траектории состояния системы.
