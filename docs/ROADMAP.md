# Следующий этап команды после версии 1.1

Выполнено 25.09.2026 (версия 1.1): эшелоны вручную и автоматически, разведение по высоте,
модель 201 с постоянным креном в ветре, петлями, порядком галсов, заходом, сносом камеры,
спиральным набором и выпуском парашюта с заданной высоты. [Описание](ECHELONS_AND_FIXED_WING.md).
Данных заказчика по 201 не будет: крен, скороподъемность, заход и высота выпуска остаются
настраиваемыми допущениями. Остаются: рельеф (DEM) — он же позволит считать потолок 150 м
над реальной поверхностью; раздельные высоты перелета и съемки; автоматический эшелон
самолета (нужен пересчет его маршрута); распределение галсов с учетом сближений; облет
препятствий самолетом между галсами; фоновые расчеты с прогрессом; проверка сборки на
машине защиты.

Выполнено 24.09.2026: автономная Windows-сборка — ZIP с собственным Python и интерфейсом,
запуск двойным щелчком без установки Python/Node.js. [Описание](WINDOWS_STANDALONE.md).
Остаются: проверка на чистой машине заказчика, сборка на актуальном выпуске Python 3.12.x
и подпись, если заказчик потребует; рельеф (DEM); облет препятствий самолетом между
галсами; фоновые расчеты с прогрессом; нелинейный заряд и «сначала зарядиться»; данные
заказчика из списка ниже.

Выполнено 24.09.2026 (версия 1.0): темная тема, работа без интернета (подложка
«Без подложки»), аудит контраста и исправления, руководство оператора, история версий.
Остаются: автономная Windows-сборка без предустановленных Python/Node.js; рельеф (DEM);
облет препятствий самолетом между галсами; фоновые расчеты с прогрессом для анализа парка;
нелинейный заряд и «сначала зарядиться»; данные заказчика — норматив ТО Gemini, время заряда
801 и 201, смысл `relativeToSeaFloor`, источник времени действия временных зон.

Выполнено 24.09.2026 (версия 0.9): интерфейс в цветах заказчика с шагами, сводками в
разделах и диаграммой расписания; зарядка на площадках (включая запасные) с очередью к ЗУ.
[Описание](UI_AND_CHARGING.md). Из списка ниже по-прежнему открыты все пункты; к ним
добавились: нелинейный заряд (замедление после 95%), вылет «сначала зарядиться», время
заряда 801 и 201 от заказчика.

Выполнено 23.09.2026 (версия 0.8): данные заказчика — импорт задания, зон и
препятствий из KML, учет высот и времени действия, исключение заблокированных
участков, повторные вылеты, срок/лимит бортов/закат, анализ парка, оценка всего
задания по пакетам, расход ресурса до ТО, формат зон KUMO.
[Описание](AIRSPACE_AND_CUSTOMER_DATA.md).

Что остается, по приоритету:
1. Автономная Windows-сборка и работа без интернета (подложка карты) — без изменений.
2. Рельеф (DEM) вместо диапазона высот: сейчас AMSL-зоны и препятствия
   сравниваются по худшему случаю, что на холмистом районе избыточно консервативно.
3. Облет препятствий самолетом между галсами (сейчас только дуги CSC).
4. Фоновые расчеты с прогрессом и отменой: анализ парка на больших пакетах идет
   десятки секунд синхронно.
5. Уточнить у заказчика: норматив ТО Gemini, смысл `relativeToSeaFloor` в их
   выгрузке (по данным — над уровнем моря), источник времени действия временных зон.

Выполнено 22.09.2026 (версия 0.7): посадка на другую подходящую основную площадку —
последний функциональный пункт «Посадка» из `DELIVERY_PLAN.md`; включается
настройкой, по умолчанию поведение прежнее. [Описание](LANDING_SITES.md).
Новые иконки БПЛА от команды без круговой подложки. [Описание](AIRCRAFT_ICONS.md).

Что остается до сдачи, по приоритету:
1. Полностью автономная Windows-сборка без установленных Python/Node.js
   (сейчас `run.bat` требует заранее подготовленных `.venv` и `npm ci`).
2. Демонстрация без интернета: погода вручную уже работает, но подложка карты
   загружается из сети — нужен офлайн-вариант или запасная подложка.
3. Материалы защиты и эталонные сценарии: основной пример и пример ошибки.
4. Данные от заказчика: размер пикселя камер 801, параметры LiDAR/магнитометра.
5. Рельеф, очередь расчетов с отменой, разделение App.tsx — после сдачи.

Выполнено 21.09.2026: первый шаг к Windows-сборке из требований заказчика —
API само отдает собранный frontend (`create_app(static_dir=...)`), `run.bat`
запускает один процесс и открывает браузер. По пути исправлен реальный баг
(Windows отдавала `.js` как `text/plain`, браузер отказывался выполнять
интерфейс). Не автономный установщик: `.venv` и `npm ci` по-прежнему нужны
заранее. [Описание и ограничения](SINGLE_PROCESS_LAUNCH.md).

Выполнено 21.09.2026: снят общий отказ для типов съемки за пределами RGB.
Мультиспектральная считается по подтвержденному профилю камеры Geoscan Pollux;
ИК, LiDAR и геофизическая принимаются с шириной захвата, заданной оператором,
поскольку подтвержденных профилей сенсора для них пока нет. [Описание и
ограничения](SURVEY_TYPES.md). Заказчик добавил мануалы 801 и Gemini: второй дал
подтвержденную вторую RGB-камеру Gemini (Sony UMC-R10C), но ни один не дал размер
пикселя матрицы для камер 801 — этот пункт остается открытым. LiDAR и
геофизическая съемка по-прежнему ждут реальных параметров сенсора от заказчика.

Выполнено 21.09.2026: проверка достижимости резервных площадок в самой удаленной
точке маршрута каждого борта, как информационная (не блокирующая) оценка.
[Описание и ограничения](RESERVE_SITES.md).

Выполнено 21.09.2026: расчет RGB по двум профилям камер, индивидуальные скорости,
Геоскан 201 и смешанный парк по демонстрационной модели. Есть пример «Демо 201»,
сохранение результатов, отчет и экспорт. [Описание](CAMERAS_AND_FIXED_WING.md).
Названные тогда следующими этапами выбор другой основной посадки и остальные
четыре вида съемки выполнены в версиях 0.7 и 0.6 соответственно.

Для дальнейшего погодного учета нужны профиль ветра по высоте и прогноз на время вылета.
Реальную телеметрию подключать после согласования протокола/SDK конкретных аппаратов.

| Участник | Ответственность |
|---|---|
| A | Интерфейс, редактор, результаты, сценарий защиты |
| B | Физические модели, сенсоры, самолет, качество планирования |
| C | API, хранение, проверки, экспорт и упаковка |

Завершен первый поток: редактирование → расчет коптеров → сравнение → экспорт.
До полного задания остаются ограничения из [PLANNING_V02.md](PLANNING_V02.md).

Приоритет следующей итерации:
1. Подготовить эталонные сценарии по заданию; уточнения заказчика внести по мере получения, не блокируя разработку.
2. Привязать RGB-покрытие к профилям камер и требуемому GSD.
3. ~~Реализовать обязательный Геоскан 201 и проверку запасных площадок.~~ Оба
   сделаны как демонстрационные модели; выбор другой основной посадки сделан в
   0.7. Пригодность самой резервной площадки (не только ее достижимость) остается.
4. Добавить рельеф и уточнить энергетику на доступных данных.
5. ~~Поддержать остальные виды съемки согласно их отдельным требованиям.~~ Все пять
   типов теперь принимаются расчетом; мультиспектральная — по камере Pollux,
   остальные три — по ширине, заданной оператором, за неимением подтвержденных
   профилей сенсора. Профиль камеры 801 и реальные параметры LiDAR/магнитометра
   остаются открытыми.
6. Вынести расчеты в очередь с прогрессом, ограничением времени и отменой.
7. Подготовить единый запуск, повторяемую демонстрацию и заморозить функции перед защитой.
