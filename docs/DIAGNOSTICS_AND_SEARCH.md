# Диагностика и поиск по интерфейсу

Версия 1.2 (17.10.2026). Код: `backend/src/bas/planning/diagnostics.py`, обработчики ошибок в
`backend/src/bas/main.py`; интерфейс — `features/diagnostics/DiagnosticsPanel.tsx`,
`features/ui/navigation.ts`, `features/search/`.

## 1. Категории

| Категория | Что значит | Примеры кодов |
|---|---|---|
| Ввод | данные не прошли проверку | `INPUT_INVALID`, `SITE_ASSIGNMENT`, `BATTERY_RESERVE`, `SPEED_LIMIT`, `COST_MODEL`, `REQUIREMENTS_EMPTY` |
| Оборудование и требования | у требования нет подходящего борта с сенсором | `EQUIPMENT_MISSING`, `GSD_LIMIT`, `CAMERA_INCOMPATIBLE`, `PAYLOAD_MISMATCH` |
| Ограничения | нарушено ограничение, которое не обойти без изменения данных | `WIND_LIMIT`, `SITE_BLOCKED`, `AREA_BLOCKED`, `CAPTURE_RATE`, `FIXED_WING_ALTITUDE` |
| План не найден эвристикой | эвристика не нашла допустимый план | `CAPACITY`, `NO_PLAN_FOUND`, `COVERAGE`, `CONFLICT` |
| Бюджет вычислений | достигнут предел объема расчета | `TOO_MANY_STRIPS`, `SEARCH_BUDGET` |
| Ошибка сервиса | внутренняя ошибка; ответ без внутренностей, с кодом для журнала | `INTERNAL` |

«План не найден эвристикой» никогда не называется невыполнимостью: сообщение прямо говорит, что
это не доказательство и что можно изменить. Невыполнимость утверждается только там, где она
следует из данных (например, у требования нет ни одного борта с сенсором нужного вида).

## 2. Структура

Каждая диагностика: `code`, `severity` (error/warning/info), `category` и `category_name`,
`title`, `message`, `subjects` (зоны, борта, площадки, требования, зоны ограничений), `actual` и
`required` с единицами, `actions` и `target` — путь к полю:

```json
{"tab": "settings", "section": "requirements", "field": "requirement:field-ms:survey_type",
 "map": {"kind": "area", "id": "field"}}
```

Ошибка расчета (HTTP 422) приходит как `{"detail": {"code", "message", "diagnostics": [...]}}`,
ошибка проверки полей — `{"detail": [...], "diagnostics": [...]}` с целью по пути поля
(`cost_model` → «Модель стоимости J», `requirements` → «Требования съемки», `settings.X` →
поле X). Замечания к построенному плану — `plan.diagnostics` (например, «не укладывается в
срок»), показываются в результате.

## 3. Действия

- **Перейти** (`navigate`): открыть вкладку, раскрыть раздел, прокрутить к полю, поставить в него
  фокус и подсветить; для площадок и зон — показать объект на карте. Введенные данные не
  меняются и не теряются.
- **Применить** (`apply`): только с предпросмотром — что изменится и при каком условии (например,
  «Добавить Pollux борту Gemini-03. Только если этот сенсор действительно есть у борта»).
  Изменение вносится по кнопке «Применить» и отменяется «Отменить» (Ctrl+Z). Сейчас единственная
  такая операция — добавить сенсор борту; она не ослабляет требования к качеству, ограничения и
  резерв. Автоматического ослабления (снизить резерв, поднять предел GSD, выключить зону) нет.

Рекомендации следуют из причины: при GSD — допустимая высота требования («не выше 51 м»); при
нехватке ресурса — площадки ближе к району, число вылетов, ограничение числа бортов, требование;
при ветре — ветер и скорость борта.

## 4. Поиск (Ctrl+K)

Кнопка «Поиск» в верхней панели или **Ctrl+K** (⌘K на Mac). Браузер использует Ctrl+K для
поиска в адресной строке; пока фокус в планировщике, сочетание открывает поиск планировщика
(перехват в фазе захвата, `preventDefault`). Повторное нажатие закрывает. Сочетание работает и
из полей ввода — в них Ctrl+K ничего не делает.

Это поиск по **каталогу команд** (`features/search/commands.ts`), а не по тексту страницы:
разделы, вкладки, отдельные настройки и действия с категорией и путем («Настройка · Параметры ›
Допущения и посадка»). Совпадение — по началу слова, по основе слова (окончания: «площадки» →
«Площадки»), по подстроке и по синонимам (аккумулятор = АКБ = батарея = заряд; БД = база данных;
камера = сенсор; ИК = тепловизор).

| Запрос | Первый результат |
|---|---|
| ветер | Погода · ветер |
| аккумулятор | Вылеты и зарядка, Резерв заряда |
| резерв | Резерв заряда |
| камера | Сенсоры бортов, Профили сенсоров |
| матрица | Матрица Q (стоимость), Профили сенсоров (матрица камеры) |
| стоимость | Модель стоимости J |
| площадка | Площадки |
| база данных | БД компании |
| экспорт | Экспорт плана · отчет, KML, GeoJSON |

Клавиатура: ↑/↓ — выбор, Enter — перейти, Esc — закрыть (фокус возвращается). Доступность: диалог
`role="dialog"`, поле `role="combobox"` со списком `role="listbox"` и `aria-activedescendant`;
«ничего не найдено» объявляется (`role="status"`).

Безопасность: выбор результата **не запускает** расчет, импорт, экспорт, сохранение и загрузку
примеров — он переводит к кнопке и подсвечивает ее (в списке помечено «действие не выполняется
без нажатия»). Сразу выполняются только безвредные действия: открыть архив, окно БД, сменить тему.

Добавить пункт — один объект в `COMMANDS`: `id`, `title`, `category`, `path`, `keywords`,
`target` (вкладка, раздел `data-section`, поле `data-nav`). Тесты `scripts/test-search.mjs`
проверяют примеры запросов, уникальность и то, что опасные действия только навигируют.
