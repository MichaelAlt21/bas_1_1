# KUMOsystems — сервис планирования авиационных работ парка БПЛА

Веб-сервис, который по району съемки, ограничениям воздушного пространства, площадкам и парку
(Геоскан Gemini, 801, 201) рассчитывает **индивидуальные полетные задания для каждого борта** и
расписание всей операции — по одному из трех критериев: «быстрее завершить», «меньше суммарный
налет» или «минимум стоимости» J = α·T + cᵀt + tᵀQt. Одна операция может включать несколько видов съемки
(например, ортофото и вегетация поля, тепловизор объекта) с разными сенсорами на бортах. Учитывает
ветер, заряд, камеры и GSD, зоны и препятствия по высоте и времени, повторные вылеты и зарядку на
площадках, разводит борта по времени и по высоте (эшелоны). Результат — маршруты на карте,
симуляция, отчет и экспорт KML/GeoJSON.

Версия 1.2 · Python 3.12, FastAPI, Shapely · React 19, TypeScript, OpenLayers 10 · 254 серверных и
52 клиентских теста · запуск на Windows без установки.

> Это инструмент предварительного планирования: план — не задание для автопилота и не
> разрешение на полеты. Каждый план перечисляет примененные допущения.

## Что умеет

- **Район и ограничения**: зоны съемки (до 200), разрешенное пространство, запреты, основные и
  запасные площадки — на карте или импортом KML заказчика: задание, зоны ограничений с высотами
  (GND/AGL/AMSL/FL) и временем действия, препятствия.
- **Парк** до 20 бортов: Gemini, 801, самолет 201 и свои профили; камеры с расчетом захвата и GSD;
  заряд, скорость, площадка, своя высота.
- **Расчет**: галсы по захвату, обход ограничений (A* в свободном пространстве), ветер, лучшая
  площадка посадки, резервные площадки, повторные вылеты с заменой АКБ или зарядкой с очередью к
  зарядным устройствам, срок и «до заката», лимит бортов.
- **Эшелоны и разведение**: 30 м по горизонтали или 20 м по высоте, точно во времени; автоматические
  эшелоны до потолка 150 м.
- **Самолет 201**: развороты с постоянным креном в ветре, пути Дубинса с петлями, облет галсов в
  выгодном порядке, заход на галс, снос камеры, набор по спирали, парашют.
- **Несколько видов съемки** (1.2): требования «зоны + вид съемки + параметры качества»; у бортов —
  списки сенсоров, один сенсор на вылет, смена нагрузки между вылетами; покрытие проверяется по
  каждому требованию; каталог профилей сенсоров с источниками и пометками «подтверждено /
  вычислено / допущение / неизвестно», свои профили с версиями, импорт и экспорт.
- **Стоимость J** (1.2): α·T + cᵀt + tᵀQt — цена срока, цена налета каждого борта и риск
  сосредоточить работу на одном борту; коэффициенты по умолчанию оценены по открытым данным с
  источниками; сравнение трех планов и график компромисса «срок — стоимость налета».
- **Диагностика и поиск** (1.2): причины отказа по категориям с переходом к полю и объекту на
  карте, исправление только с предпросмотром и отменой; поиск по разделам и настройкам (Ctrl+K).
- **Решения для заказчика**: анализ парка — сколько бортов нужно к сроку; оценка всего задания по
  пакетам работ в днях.
- **Результат**: показатели, диаграмма расписания, симуляция, таблица вылетов, расход ресурса до ТО,
  печатный отчет, KML/GeoJSON плана и каждого борта, архив расчетов; светлая и темная тема;
  работа без интернета.

Несколько цифр из проверок: пример «201 + Gemini» — налет 32,4 → 26,4 мин после новой модели
самолета; 20 Gemini на 4 площадках — срок 33,5 → 23,9 мин с разведением по высоте; пример
«Эшелоны» — общие участки маршрутов на одной высоте 8,2 → 0,3 км. Расчет — секунды.

## Быстрый старт

**Без установки (Windows 10/11 x64).** Распакуйте `KUMOsystems-1.2.0-win64.zip` и дважды щелкните
`KUMOsystems.cmd` — откроется браузер на http://127.0.0.1:8000. Python и Node.js не нужны; окно
консоли — это сервер. Сборка архива: `.\scripts\build-windows.cmd`
([подробнее](docs/WINDOWS_STANDALONE.md)).

**Из исходников** (Python 3.11+, Node.js 18+), из папки проекта:

```powershell
cd backend; python -m venv .venv; .\.venv\Scripts\python.exe -m pip install -e '.[dev]'; cd ..
cd frontend; npm ci; npm run build; cd ..
.\run.bat
```

`run.bat` запускает один процесс сервера, который отдает API и интерфейс, и открывает браузер.
Swagger UI — http://127.0.0.1:8000/docs.

**Разработка** — два терминала:

```powershell
cd backend; .\.venv\Scripts\python.exe -m uvicorn bas.main:app --reload --host 127.0.0.1 --port 8000
cd frontend; npm run dev   # http://localhost:5173; при первом запуске: Copy-Item .env.example .env.local
```

Спутниковая подложка — свой ключ MapTiler в `frontend/.env.local` ([MAPS.md](docs/MAPS.md)).
Без ключа доступны OpenStreetMap и режим «Без подложки».

## Демонстрация

В шапке четыре примера — откройте и нажмите «Рассчитать план» или «Сравнить 3»:

- **Пример: коптеры** — Gemini и 801 с двух площадок, запретная зона, запасная площадка.
- **Пример: виды съемки** — поле (ортофото и вегетация) и завод (тепловизор); борта с разными
  сенсорами; «Сравнить 3» показывает, чем различаются планы трех критериев.
- **Пример: 201** — самолет и Gemini с камерами: развороты, облет галсов, парашют, GSD.
- **Пример: эшелоны** — 8 Gemini с двух площадок: общие коридоры разводятся по высоте.

Сценарий показа, ключевые цифры и ответы на вероятные вопросы — [PRESENTATION.md](docs/PRESENTATION.md).

## Проверки

```powershell
cd backend; .\.venv\Scripts\python.exe -m pytest -q; cd ..
cd frontend; npm test; npm run build; cd ..
```

254 серверных и 52 клиентских теста. Эталонные расчеты примеров (`scripts/benchmark.py`): в 1.2 общий
локальный поиск улучшил 9 из 20, остальные совпадают с 1.1 побитово. Все проверки и замеры — [VERIFICATION.md](docs/VERIFICATION.md).

## Структура

```text
backend/     сервер: API (FastAPI), расчетное ядро planning/, импорт KML, экспорт, тесты
frontend/    интерфейс: React + OpenLayers, клиентские тесты в scripts/
contracts/   примеры сценариев и зон — тестовые сценарии демонстрации
docs/        документация
scripts/     запуск из исходников, автономная сборка, пакет исходников, проверки
```

Пакет исходников для публикации без локальных файлов и ключей:
`backend\.venv\Scripts\python.exe scripts\package_source.py` → `dist-source/`.
